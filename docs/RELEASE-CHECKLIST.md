این چک‌لیست برای همه نسخه‌های آینده است. هر مورد فقط پس از اجرای واقعی علامت زده شود.

## ۱. حفاظت و backup

- [ ] هدف، شماره نسخه و دامنه تغییرات تأیید شده است.
- [ ] `AGENTS.md` کامل خوانده شده است.
- [ ] backup دیتابیس و فایل‌های لازم تهیه و امکان restore آن بررسی شده است.
- [ ] SHA-256 یا روش صحت‌سنجی backup ثبت شده است.
- [ ] برنامه rollback و مسئول تصمیم بازگشت مشخص است.
- [ ] داده، credential، مسیر خصوصی یا فایل آزمایشی وارد مخزن نشده است.

## ۲. بررسی Git و دامنه تغییر

- [ ] شاخه درست و ارتباط آن با remote بررسی شده است.
- [ ] `git status` اولیه ثبت شده است.
- [ ] فهرست modified و untracked بررسی شده است.
- [ ] diff کامل به نیازهای تأییدشده منتسب شده است.
- [ ] `.gitignore` و `AGENTS.md` ناخواسته تغییر نکرده‌اند.
- [ ] conflict marker، backup، log، SQL، ZIP قدیمی و فایل Local وجود ندارد.
- [ ] بازنویسی گسترده line ending رخ نداده است.

## ۳. آزمون ایستا

- [ ] تمام فایل‌های PHP بسته با `php -l` بررسی شده‌اند؛ تعداد ثبت شود.
- [ ] تمام فایل‌های JavaScript تغییرکرده با `node --check` یا parser معتبر بررسی شده‌اند.

- [ ] `git diff --check` موفق است.

- [ ] ضرورت تغییر `HAMNOOR_DB_VERSION` مستند شده است.
- [ ] migration دارای نسخه مستقل یا نسخه DB روشن است.
- [ ] نصب تازه schema درست می‌سازد.
- [ ] ارتقا از نسخه‌های پشتیبانی‌شده داده را حفظ می‌کند.
- [ ] migration تکرارشونده و idempotent است.
- [ ] جدول‌ها، ستون‌ها، indexها و optionهای مورد انتظار کنترل شده‌اند.
- [ ] مسیر شکست و rollback migration بررسی شده است.
