# نقشه راه هم‌نور

آخرین به‌روزرسانی: ۱۵ ژوئیه ۲۰۲۶

این سند فقط پیشنهادهایی را ثبت می‌کند که از کد، TODOها یا اسناد فعلی مخزن قابل ردیابی‌اند. هیچ موردی تعهد انتشار نیست مگر اینکه مالک محصول آن را تأیید کند.

## پیشنهادهای نسخه 2.8.x

- **پیشنهادی — تکمیل matrix آزمون:** اجرای دوره‌ای smoke test روی PHPهای پشتیبانی‌شده، وردپرس واقعی، یک قالب بلوکی و یک قالب کلاسیک.
- **پیشنهادی — آزمون integration سئو:** بررسی زنده canonical، sitemap و noindex با نسخه‌های مورد استفاده Yoast SEO و Rank Math.
- **پیشنهادی — آزمون‌های مرورگر:** پوشش AJAX، modal، overflow موبایل، Web Share و حالت بدون JavaScript.
- **پیشنهادی — همگام‌سازی اسناد قدیمی:** بازبینی جداگانه اسناد معماری ریشه که هنوز 2.6.0/RC را عنوان می‌کنند، بدون حذف تاریخچه معتبر آن‌ها.
- **پیشنهادی — کنترل CI انتشار:** اجرای خودکار PHP lint، JavaScript syntax، `git diff --check` و کنترل ساختار ZIP؛ نیازمند تصمیم درباره زیرساخت GitHub Actions.

## پیشنهادهای نسخه 2.9.0

- **پیشنهادی و مشروط به داده عملیاتی — هویت participant:** بررسی migration یک `identity_hash` برای کاهش duplicate در concurrency بسیار بالا. semantics ادغام موبایل/ایمیل باید پیش از طراحی تأیید شود.
- **پیشنهادی و مشروط به مقیاس — انتخاب تصادفی:** جایگزینی `ORDER BY RAND()` با sampling کم‌هزینه‌تر، فقط اگر اندازه dataset یا اندازه‌گیری performance ضرورت را نشان دهد.
- **پیشنهادی — بهبود مرزبندی کنترلر:** انتقال تدریجی AJAX و HTML باقی‌مانده از Frontend controller، فقط همراه با آزمون regression مسیرهای create/claim/complete/release/track.
- **پیشنهادی — آزمون migration ارتقا:** سناریوهای خودکار ارتقا از نسخه‌های دارای داده قدیمی، به‌ویژه migration مستقل محدودیت تکرار.

## اهداف بلندمدت

- **پیشنهادی — اکوسیستم ادان:** provider پیامک، notification queue، reminder، QR، گزارش پیشرفته و template pack به‌صورت افزونه مستقل و بدون patch هسته.
- **پیشنهادی — پرداخت مستقل:** هر قابلیت پرداخت/نذر با جدول transaction، endpoint و credential مستقل در ادان پیاده شود؛ بخش حمایت داوطلبانه هسته نباید به پرداخت اجباری تبدیل شود.
- **پیشنهادی — احراز هویت اختیاری قوی‌تر:** OTP login یا policyهای حساس‌تر در ادان authentication، با حفظ مسیر ساده فعلی فقط در صورت تأیید مالک محصول.
- **پیشنهادی — گزارش تحلیلی:** read model یا جدول aggregate متعلق به ادان برای analytics حجیم؛ جدول log هسته audit پایه باقی بماند.

## بدهی‌های فنی

- SQL اصلی در `Hamnoor_DB` متمرکز است و Repositoryها هنوز abstraction نازکی دارند.
- AJAX فرانت‌اند در `Hamnoor_Frontend` باقی مانده است.
- بخشی از HTML بزرگ همچنان در کنترلر Frontend تولید می‌شود.
- rate limiter transient-based در زیرساخت چندسروری به object cache مشترک یا WAF نیاز دارد.
- fallback خروجی XLSX به CSV باید در محیط‌هایی که `ZipArchive` ندارند مستمر آزموده شود.
- اسناد معماری 2.6.0 اطلاعات معتبر تاریخی را با ادعاهای وضعیت RC در یک فایل ترکیب کرده‌اند.
- نبود گزارش CI دائمی در مخزن فعلی؛ ایجاد CI نیازمند تأیید است.

## موارد نیازمند تصمیم مالک محصول

- **نیازمند تأیید:** اولویت واقعی میان SMS، reminder، QR، پرداخت، گزارش پیشرفته و template pack.
- **نیازمند تأیید:** ادامه پیگیری ساده تماس‌محور یا الزام OTP برای سایت‌های حساس.
- **نیازمند تأیید:** آستانه داده/بار که migration `identity_hash` یا حذف `ORDER BY RAND()` را توجیه می‌کند.
- **نیازمند تأیید:** نسخه‌های WordPress و PHP که باید در matrix رسمی CI پشتیبانی شوند.
- **نیازمند تأیید:** ایجاد GitHub Actions و سیاست نگهداری artifactهای ZIP.
- **نیازمند تأیید:** زمان مناسب برای به‌روزرسانی یا آرشیوی‌کردن اسناد قدیمی 2.6.0؛ در این مأموریت حذف یا جابه‌جا نشده‌اند.
